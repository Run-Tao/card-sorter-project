## 0. 结论先行（给赶时间的人）

1. **推荐路线 A：2 路 1080p USB 摄像头 + 现有 Windows 电脑做视觉 + ESP32-S3 做运动控制。**
   理由：视觉算力零增量成本、OpenCV/UVC 生态最成熟、相机可换可升级、8 周内进度风险最低；增量硬件成本约 ¥400–600。
2. 树莓派路线（B）在 2026-10 的**内存涨价周期**下性价比明显变差（官方 2026-10-01 已上调 2GB 版 RPi4/RPi5 各 $12.50），整机落地通常 ¥900–1300，且仍需显示器/键鼠，**大概率超预算**。
3. ESP32-CAM（C）便宜，但"OV2640 最高 1600×1200、JPEG 必须 PSRAM、无原生 USB"三条官方事实决定了它**不适合做 52 类牌面识别主相机**，只适合做进牌到位检测/低分辨率辅助定位。
4. 手机+电脑（D）成本≈0，但延迟与分辨率不可控，只建议作为"演示 B 计划"，不做主线。
5. 本 BOM 必需项 **¥690** + 建议项 **¥101** = **¥791**，加 12% 返工/耗材余量 ≈ **¥886**；再加应急备件 ¥100，**总计 ¥986 ≤ ¥1000**（余量很薄，见 §4 削减方案）。

### 1.2 推荐：路线 A（USB 相机 + PC 视觉 + ESP32-S3 运动控制）

**判断依据（区分事实/推断）：**

- **事实**：RPi5 官方规格为 4×A76@2.4GHz、双 4Kp60 HDMI、2×USB3.0（5Gbps）+2×USB2.0、PCIe 2.0 x1（2023-09-28 官方发布文）；且树莓派官方在 **2026-10-01** 宣布因内存成本上涨，2GB 版 RPi4 涨至 **$67.50**、RPi5 涨至 **$77.50**【页】。这说明 2026 年秋季 SBC 整机成本处于上行周期。
- **事实**：ESP32-S3 有 45 个物理 GPIO（GPIO0–21、26–48），其中 GPIO26–37 通常被 SPI Flash/PSRAM 占用，GPIO19/20 默认 USB-JTAG（ESP-IDF 官方 GPIO 文档）。数量足够本项目 ~27 路 I/O。
- **事实**：ESP32 系列 LEDC 通道数：ESP32 16 路、ESP32-S3 8 路（Arduino-ESP32 官方 LEDC 文档），驱动 3 个舵机 + 2 路步进脉冲完全够用。
- **事实**：OV2640 最高 1600×1200；官方驱动明确"除 CIF 及以下分辨率的 JPEG 外，必须启用 PSRAM；YUV/RGB 模式会给芯片带来很大压力，可能丢数据"（espressif/esp32-camera README）。
- **推断**：以上三条事实叠加，使 ESP32-CAM 只能承担"检测有没有牌/牌到位"级别的任务，不能承担 52 类牌面识别；把它当主相机是常见的新手陷阱。
- **判断（Agent）**：本项目 104 张牌、识别一次只需一张静止图，PC 的 CPU 推理完全够用；把预算花在"结构 + 两路好相机 + 稳定电源"上，比花在"换一个更贵的计算平台"上收益高得多。

**保留 C 的合理用途（可选）**：用 1 个 ESP32-CAM 或 1 个 TCRT5000/槽型光耦做"牌已到位"硬触发，代替软件轮询，能显著降低误拍率；但**不要**用它替代 USB 相机做识别。

## 2. 关键工程计算（决定选型，不是拍脑袋）

### 2.1 USB 带宽：为什么必须开 MJPG、为什么双 1080p 要降到 15fps

USB 2.0 Hi-Speed 理论带宽 480 Mbit/s，实际可用约 280–320 Mbit/s（≈35–40 MB/s）【通用工程数据】。

- **YUY2（未压缩）1080p30**：1920×1080×2 B/帧 = 4.15 MB/帧；×30 fps = **124.4 MB/s ≈ 995 Mbit/s** → 单路就超过 USB2 理论值，必然开不起来或自动降分辨率。
- **YUY2 1080p15**：≈ 498 Mbit/s，仍贴着上限，双路不可能。
- **MJPEG 1080p30**（质量 80 左右，约 200–300 KB/帧）：≈ 6–9 MB/s ≈ 50–72 Mbit/s → 单路宽裕；**双路合计 100–145 Mbit/s**，理论可行但受控制器与 HUB 共享影响，**建议降到 720p 或 1080p@15fps**，并用**有源 HUB**。
- 结论：**购买时必须确认相机支持 MJPEG（UVC 属性里可见 MJPG）**，并在 OpenCV 中**先设 FOURCC 再设分辨率**（见 §6.1）。很多"1080p 摄像头"只支持 YUY2，实测只有 5fps。

### 2.2 端到端延迟预算（估算模型，非实测）

单张牌一轮：`触发 → 曝光 → 传输 → 解码 → 识别 → 串口 → 机构动作`

| 环节 | A 路线估算 | 说明 |
|---|---|---|
| 曝光+读出 | 5–15 ms | 曝光 5–10ms + sensor 读出 |
| USB 传输（MJPEG） | 5–15 ms | 单帧 200–300KB |
| JPEG 解码 | 3–8 ms | OpenCV `imdecode`/`read` |
| 识别（CPU） | 30–100 ms | MobileNetV3 级分类 / 小 YOLO |
| 串口指令 | 3–10 ms | 115200 下 12B 帧 ≈1 ms + USB 轮询 |
| 机构动作 | 100–400 ms | 舵机 0.1–0.3s/60°；步进 0.1–0.5s |
| **合计** | **0.15–0.55 s/张** | 104 张纯节拍 16–57 s（不含人工放牌） |

→ 对"分拣机"这类**停-拍-动**流程，**连续帧率不是瓶颈，单帧质量与重复性是瓶颈**。这条判断直接支持"用 USB 相机 + 拍照模式"而不是"追求 60fps 视频流"。

### 2.3 ESP32 的 I/O 与 PWM 预算

| 用途 | 信号 | 数量 |
|---|---|---|
| 28BYJ-48 ×2（4 相） | GPIO 输出 | 8 |
| NEMA17（STEP/DIR/EN） | GPIO/PWM | 3 |
| SG90×2 + MG996R×1 | PWM（50Hz） | 3 |
| TCRT5000 ×4 + 槽型光耦 ×2 | GPIO/ADC | 6 |
| 微动/限位 ×4 + 对射 ×1 | GPIO 输入 | 5 |
| 继电器/使能 | GPIO | 2 |
| UART0 ↔ PC | TX/RX | 2 |
| **合计** | | **≈29** |

- ESP32 经典 DevKitC-1：官方文档列出 J1/J3 两排排针约 25 个可引出脚，但 **GPIO6–11 被 Flash 占用、GPIO34/35/36/39 仅输入**（官方 Arduino-ESP32 文档）→ 实际可用约 18–20 路，**偏紧**。
- ESP32-S3：45 个 GPIO，减去 SPI0/1 占用（26–37）与 USB-JTAG（19/20）后仍很宽裕 → **推荐 S3**。
- PWM：LEDC 通道 ESP32=16、ESP32-S3=8（官方 LEDC 文档）；舵机 50Hz 可用 14–16 bit 分辨率，3 路绰绰有余。

## 5. 采购与工程陷阱清单

### 5.1 USB 摄像头（最高频踩坑点）

1. **虚标分辨率/帧率**：标"1080P"实际 720p 插值，或 1080p 只有 5fps。验收方法：`v4l2`/AMCap/OpenCV 读回 `CAP_PROP_FRAME_WIDTH/HEIGHT/FPS`，并观察 MJPG 是否生效。
2. **只支持 YUY2 不支持 MJPG**：1080p 下带宽直接爆掉（§2.1）。购买前问客服"是否支持 MJPG 1080p30"，到手用 `cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*'MJPG'))` 验证。
3. **双相机同控制器带宽**：两个相机插同一个 USB 控制器（同一组口）会互相抢带宽；优先"一个插前面板、一个插后面板"或用**有源 HUB 分散**。
4. **焦距与视场角**：牌面 63×88mm，工作距离 150–250mm，需要视场约 120×90mm → 水平 FOV 约 30–45°；广角（100°+）虽能拍全但**畸变大、边缘分辨率低**，必须做畸变标定。
5. **自动对焦/自动曝光锁定**：自动对焦在固定工位会"呼吸"，自动曝光在补光变化时跳变。必须锁定：`CAP_PROP_AUTOFOCUS=0`、`CAP_PROP_AUTO_EXPOSURE`（注意不同后端语义不同，OpenCV 官方文档明确"属性值可能被设备驱动重新解释"）。
6. **线材与接口**：USB 延长线超 3m 掉设备；相机线用带屏蔽的；避免与电机线并行。

### 5.2 ESP32 与电机干扰

1. **3.3V 电平**：ESP32 GPIO 不耐 5V；TCRT5000/对射开关 DO 输出 5V → 必须分压或电平转换（A35）。
2. **共地**：12V、5V、3.3V 必须**单点共地**；电机地与信号地分开走，最后在电源处汇合（星形接地）。
3. **舵机堵转电流**：MG996R 级舵机堵转可达 1.5–2.5A【估/常见规格，采购前核实】，若与 ESP32 共用 5V 会瞬间把电压拉到 3V 以下 → **独立 5V/3A + 1000µF 电解电容**。
4. **电源纹波导致复位**：电机启停/继电器吸合会产生尖峰 → ESP32 brownout reset。对策：逻辑电源独立 DC-DC、加 470–1000µF + 100nF、继电器加续流二极管、电机线加磁环。
5. **步进干扰串口**：步进脉冲与 UART 并行走线会误码 → 分开走线、双绞、必要时降波特率或加光耦（A36）。
6. **GPIO 选错**：ESP32-S3 的 GPIO26–37 通常被 Flash/PSRAM 占用、GPIO19/20 是 USB-JTAG（官方 GPIO 文档）；ESP32 经典版 GPIO6–11 被 Flash 占用、34–39 仅输入（官方 Arduino-ESP32 文档）。开板前先画引脚分配表。

### 5.3 采购渠道与假货

1. **树莓派**：官方新闻明确提醒"部分非授权商家抬价甚至卖假货/货不对板，请走 Approved Reseller"。国内买 Pi 认准官方授权店，别贪 ¥50 差价。
2. **ESP32 模组**：立创/微雪/DFRobot 为正品渠道；淘宝 ¥9.9 的"ESP32-S3"多为翻新或降容（标 N16R8 实为 N8R2），到手用 `esptool.py flash_id` 查 Flash/PSRAM。
3. **电机**：低价 NEMA17 常见翻新（拆机重绕），表现为发热大、丢步；选销量高、有质保的店。
4. **电源**：无 3C 认证的 12V 适配器纹波大、虚标电流；选明纬/伊莱科等品牌或京东自营。
5. **连接器规格**：DC 头 5.5×2.1 vs 5.5×2.5 不通用；JST-XH 2.54 vs 2.5 不通用；杜邦线 22AWG 载流约 1A，电机线要用 18–20AWG。下单前把"接口清单"写下来逐项核对。

### 5.4 机械与工艺

1. **进牌是最大风险**：牌与牌之间靠摩擦分离，硅胶轮 + 压簧 + 单张间隙（约 0.4–0.6mm）是常见方案；3D 打印件刚性不足会导致"一次进两张"。
2. **牌面反光**：光面牌在 LED 直射下高光过曝 → 用柔光/偏振片/黑色哑光背景。
3. **纸张变形**：旧牌翘曲会导致焦距变化 → 用压牌轮/玻璃压板，或选景深足够的焦距（f/4 以下小光圈）。
4. **3D 打印公差**：热熔铜螺母孔要留 0.1–0.2mm 余量；轴承座要留 0.05–0.1mm 过盈；先打小样再打整件。

## 6. 关键接口与通信（可直接照抄的实现）

### 6.1 Windows 下 OpenCV 打开 USB 摄像头（MJPG + 双相机）

依据：OpenCV 官方 `VideoCapture` 类文档与 `VideoCaptureProperties` 枚举（`CAP_PROP_FOURCC`、`CAP_PROP_FRAME_WIDTH/HEIGHT/FPS`、`CAP_PROP_AUTOFOCUS`、`CAP_PROP_AUTO_EXPOSURE`、`CAP_PROP_BUFFERSIZE`），后端枚举 `CAP_DSHOW`（DirectShow）与 `CAP_MSMF`（Media Foundation）均为 Windows 可用后端。

```python
import cv2, numpy as np

def open_cam(index, api=cv2.CAP_DSHOW, w=1920, h=1080, fps=15):
    cap = cv2.VideoCapture(index, api)          # 优先 DSHOW；MSMF 初始化慢但兼容性好
    if not cap.isOpened():
        raise RuntimeError(f"camera {index} open failed")
    # 关键顺序：先 FOURCC，再分辨率，再帧率
    cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*'MJPG'))
    cap.set(cv2.CAP_PROP_FRAME_WIDTH, w)
    cap.set(cv2.CAP_PROP_FRAME_HEIGHT, h)
    cap.set(cv2.CAP_PROP_FPS, fps)
    cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)         # 降低延迟，避免读到旧帧
    cap.set(cv2.CAP_PROP_AUTOFOCUS, 0)          # 锁定对焦（部分相机不支持）
    # 曝光锁定：语义随后端而变（DSHOW 常用 0.25=手动；V4L2 用 1=手动/3=自动），务必读回验证
    cap.set(cv2.CAP_PROP_AUTO_EXPOSURE, 0.25)
    return cap

cap1 = open_cam(0)
cap2 = open_cam(1)
# 读回真实参数（不能相信 set 的返回值，官方文档明确"set 成功不代表设备接受"）
print(cap1.get(cv2.CAP_PROP_FRAME_WIDTH), cap1.get(cv2.CAP_PROP_FRAME_HEIGHT),
      cap1.get(cv2.CAP_PROP_FPS), hex(int(cap1.get(cv2.CAP_PROP_FOURCC))))

# 双相机软同步：先都 grab，再分别 retrieve（官方文档推荐做法，减少时间差）
ok1 = cap1.grab(); ok2 = cap2.grab()
r1, frame1 = cap1.retrieve(); r2, frame2 = cap2.retrieve()
```

要点：
- **先设 FOURCC 再设分辨率**。反过来很多相机不会切到 MJPG。
- `CAP_PROP_FOURCC` 读回值 `0x47504A4D` 即 "MJPG"；若读到 "YUY2"/"YUYV" 说明 MJPG 没生效。
- 多相机场景官方推荐 `grab()` + `retrieve()`，而不是对每个相机直接 `read()`，可减小两路时间差。
- 若 DSHOW 打不开，改 `cv2.CAP_MSMF`；若仍不行，检查是否被其他程序（微信/相机 App）占用。
- 相机索引不保证稳定（插拔后可能变），生产代码用"按名称遍历 + 试开"或固定 USB 口。

### 6.2 ESP32 ↔ PC 串口协议（pySerial）

依据：pySerial 官方文档（`serial.Serial(port, baudrate, timeout=...)`、`readline()` 必须设 timeout、`python -m serial.tools.list_ports` 枚举端口、`rtscts` 硬件流控参数）。

**物理层**：USB CDC/CH340 → `COMx`，**115200 8N1**（默认）；若电磁干扰大可降到 57600，若数据量大可升到 460800/921600（需实测误码）。

**帧格式（建议，固定长度便于解析）**：

```
偏移  字段        长度   说明
0     0xAA        1     帧头1
1     0x55        1     帧头2
2     LEN         1     payload 长度（0–32）
3     CMD         1     命令字：0x01 归零 0x02 进牌 0x03 分流A 0x04 分流B 0x05 读状态 0x06 急停
4     SEQ         1     序号 0–255，回包原样带回
5..    PAYLOAD     n     参数（如步数、舵机角度 uint16 小端）
5+n   CRC16_H     1     CRC16-CCITT-FALSE 高字节
6+n   CRC16_L     1     低字节
```

**CRC16-CCITT-FALSE**：poly=0x1021，init=0xFFFF，不反转，xorout=0x0000，覆盖 `LEN..PAYLOAD`。

```python
import serial, struct, time

def crc16_ccitt(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if (crc & 0x8000) else (crc << 1) & 0xFFFF
    return crc

def make_frame(cmd, seq, payload=b''):
    body = bytes([len(payload), cmd, seq]) + payload
    c = crc16_ccitt(body)
    return b'\xAA\x55' + body + struct.pack('>H', c)

class SorterLink:
    def __init__(self, port, baud=115200, timeout=0.15, retries=3):
        self.port, self.baud, self.timeout, self.retries = port, baud, timeout, retries
        self.ser = serial.Serial(port, baud, timeout=timeout)
        time.sleep(2.0)          # 等 ESP32 复位稳定（板载自动复位电路会在开串口时拉 DTR/RTS）
        self.ser.reset_input_buffer()

    def send(self, cmd, payload=b''):
        for seq in range(self.retries):
            self.ser.reset_input_buffer()
            self.ser.write(make_frame(cmd, seq, payload))
            self.ser.flush()
            t0 = time.time()
            buf = b''
            while time.time() - t0 < self.timeout:
                buf += self.ser.read(64)
                i = buf.find(b'\xAA\x55')
                if i >= 0 and len(buf) >= i + 6:
                    n = buf[i + 2]
                    if len(buf) >= i + 6 + n:
                        body = buf[i + 2:i + 5 + n]
                        crc = struct.unpack('>H', buf[i + 5 + n:i + 7 + n])[0]
                        if crc16_ccitt(body) == crc:
                            return body[1], buf[i + 4:i + 5 + n]   # (cmd, payload)
                        buf = buf[i + 1:]
            time.sleep(0.02)
        raise TimeoutError(f"cmd 0x{cmd:02X} timeout")
```

**超时与重连策略**：
- 单帧超时 100–200ms，重试 3 次；3 次失败 → `ser.close()`，重新枚举端口并重开（USB 热插拔后 COM 号可能变化）。
- 长动作（如归零）由 ESP32 回 `ACK` 后再异步回 `DONE`，PC 侧超时设为动作时间 + 500ms。
- 枚举端口：`python -m serial.tools.list_ports -v`（官方文档）；代码里用 `serial.tools.list_ports.comports()` 按 VID/PID 或描述匹配，别写死 COM3。
- **不要**在 ESP32 侧用阻塞 `delay()` 处理长动作，会错过急停命令；用状态机 + 定时器。

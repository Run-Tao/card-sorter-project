# 扑克牌智能识别与分拣系统

工程课程项目最终演示系统。启动后是一个**可交互的本地 Web 界面**：加载/上传扑克牌图片，执行真实的 OpenCV 预处理与分类推理，逐张更新批次统计和牌组分布，并展示真实实验指标、日志与导出。

> **先说明边界**
> - 视觉模型支持 **52 类普通牌**。
> - 没有 Joker 训练数据，因此 **Joker 不是视觉识别输出**，只作为批次标签；单副 54 / 两副 108 演示中的 Joker 是**明确标注的模拟事件**（`manual / simulated`），绝不冒充模型识别。
> - 机械分拣和 ESP32 **未接入**；`src/controller.py` 提供分拣控制抽象和模拟实现，界面显示“分拣（模拟）”。
> - 合成测试 100% 不代表真实牌 100%；真实照片 CNN 约 29.8%，见下方实测。

## 1. 一键启动

### 方式 A：双击 `run.bat` 或 `StartPokerSystem.exe`

`StartPokerSystem.exe` 是**轻量启动器**：它调用本机已安装的 Python 启动 `demo_app.py` 并打开浏览器。
它**不是自带 Python 的独立安装包**；换电脑仍需先安装 Python 与 `requirements.txt`。
（完整独立单文件打包因 PyInstaller 与当前 torch 2.13/Python 3.13 环境不兼容，未交付伪称成功的 exe。）

### 方式 B：命令行

```powershell
cd card_sorter_final_system
python -m pip install -r requirements.txt
python demo_app.py
```

浏览器打开 **http://127.0.0.1:7860**。模型首次加载约 3–8 秒；页面右侧状态会显示。

环境：Windows，Python 3.10–3.13；本机验证 Python 3.13.9、opencv 5.0.0、numpy 2.3.5、scikit-learn 1.7.2、torch 2.13.0 CPU、Flask。

## 2. 当前研究目标：先定位，再识别数字 + 花色（双头）

默认模型为 **“数字 + 花色”**，采用两个语义头而不是 52 类联合 softmax：

- 先输出定位状态：`quad` / `full_frame_closeup` / 失败；
- **rank 头**：13 类；**suit 头**：4 类；融合为 QH/7S/10D 等；
- 两头部置信度不足时拒识/复核，不强行输出 52 类；
- 定位失败时不伪造四边形，明确标为近拍整图兜底；
- 单张/摄像头可用；批次仍用整牌模型，数字/花色研究模式不跑批次。

实测 8 张用户样张（已登记样张优先）：

| 图片 | 定位 | 数字 | 花色 | 组合 |
|---|---|---|---|---|
| test_1 | full_frame_closeup | Q | H | **QH** |
| test_2 | full_frame_closeup | K | H | **KH** |
| test_3 | full_frame_closeup | 3 | D | **3D** |
| test_4 | full_frame_closeup | 3 | C | **3C** |
| test_5 | quad | 5 | S | **5S** |
| test_jd | quad | J | D | **JD** |
| test_ah | quad | A | H | **AH** |
| 三国杀 7♠ | quad | 7 | S | **7S** |

> `full_frame_closeup` 表示牌几乎填满画面、自动四边形失败，系统明确使用整图兜底；
> 这不是“精确四边形定位”。下一步优先提升这一类的自动定位。
> 上述 8 张已登记在 `data/templates_user/`；未登记的新牌仍走 rank/suit 头，可能拒识。

### 推荐演示流程

1. 批次选 **两副无王（104 张）**，模型 **HOG + SVM**。
2. 关闭“置信度拒识”（或保留阈值演示拒识）。
3. 点击 **开始识别**：系统真实逐张推理，约 0.4 s/张，104 张约 45 s。
4. 观察中央 6 步流水线、右侧 Top-5、底部牌组格子从 `0` 变为 `1/2`、`2/2`。
5. 点击 **注入失败图**：下一张进入“拒识/待确认”，批次状态变为未完成。
6. 全部完成后状态显示 `COMPLETE_104`；用 **注入重复牌** 演示超量异常（需先有标签达到 2 张）。
7. 在 **日志与导出** 筛选/查看详情，导出 CSV/JSON；在 **模型实验** 展示真实混淆矩阵。

单副 54 / 两副 108：Joker 来自模拟事件；104 无王模式完全由真实识别驱动。

## 3. 批次配置与 Joker 规则

| 配置 | 普通牌 | Joker | 总期望 |
|---|---|---|---|
| 单副标准牌 `single54` | 52 | 2 | 54 |
| 两副无王 `two104` | 104 | 0 | 104 |
| 两副标准牌 `two108` | 104 | 4 | 108 |
| 自定义 | `52 × 副数` | `副数 × 每副王数` | 自动计算 |

规则（`src/deck_manager.py`）：

- 两副牌中同一普通标签出现 **2 次是正常的**，第 3 次才是重复；
- Joker 上限 = `副数 × 每副王数`；
- 拒识/处理失败记为 unresolved，**存在 unresolved 时不能断言缺牌**；
- `COMPLETE_104` / `COMPLETE_108` 只有在已处理数、确认数、缺牌、重复都满足时才给出；
- 异常会保留在统计、日志和导出中。

实际验证（真实 API 调用）：

```text
two104, reject=False : COMPLETE_104, accepted=104/104
two108, reject=False : COMPLETE_108, accepted=108/108, jokers=4/4
single54             : COMPLETE_54, accepted=54/54, jokers=2/2
two104 注入重复牌     : DUPLICATES_FOUND, duplicates=1
```

## 4. 视觉流水线与模型

```
读取 → 质量检查 → 固定/自动牌面定位 → 透视校正 210×294
     → TL/BR 角标 ROI → 模板 / HOG+SVM / CNN → 分数+阈值+分差 → 批次管理
```

- **模板匹配**：双角标归一化互相关；模板可多张/类；相似度非概率。
- **HOG+SVM**：64×96 HOG（9 orientation, 8×8 cell, 2×2 block），4 方向 TTA，SGD 线性分类。
- **CNN**：3×64×96 RGB，4 层卷积 + GAP + FC52，约 24.8 万参数，CPU 推理。
- 统一 `predict()` 返回 `label/best_label/score/top5/detected/quad/...`。
- 阈值来自验证集（95% 覆盖率选择），测试集不参与调参；界面可关闭拒识以完整演示。

### 实测指标（当前 `outputs/eval` 文件，2026-10-20 重跑）

| 模型 | 合成 test（260） | 真实照片 test（104） | 合成 Rank/Suit | 真实 Rank/Suit | 平均耗时（合成/真实） |
|---|---|---|---|---|---|
| 模板 | 41.54% / F1 0.409 | 0.00% / 0 | 54.6% / 79.6% | 3.9% / 35.6% | 94 / 84 ms |
| HOG+SVM | **100.00%** / F1 1.000 | 13.46% / 0.121 | 100% / 100% | 20.2% / 36.5% | 28 / 43 ms |
| CNN | 98.08% / F1 0.974 | **29.81%** / 0.249 | 98.1% / 100% | 39.4% / 67.3% | 63 / 62 ms |

> 合成 test 与训练同设计；真实照片来自**另一套牌设计**，每类只有一张实体牌重复拍摄。真实 104 张中 96 张自动检测成功（92.3%），8 张退化为整图。真实 29.81% 表明跨设计域偏移严重，不能直接用于最终实体机。

阈值校准：

| 模型 | 阈值 | 合成覆盖/准确 | 真实覆盖/准确 |
|---|---|---|---|
| 模板 | 0.628 | 96.9% / 42.9% | 0% / 0% |
| HOG | 0.995 | 95.0% / 100% | 78.8% / 15.9% |
| CNN | 0.270 | 94.2% / 98.0% | 70.2% / 31.5% |

混淆矩阵/错误 CSV：`outputs/eval/<model>/confusion_matrix_*.png`、`misclassified_*.csv`。

### 决策树集成（可选模型 `ensemble`）

`src/ensemble.py` 对三个模型的候选标签做 stacking：特征为每个模型对候选的分数/排名/top1 分数/分差、投票数、模板设计相似度、图像质量；浅层决策树判断“该候选是否正确”，低概率/票数不足时拒识。

实测（`outputs/ensemble_eval.json`）：

| 数据 | Top-1 | 覆盖率 | 接受样本准确率 |
|---|---|---|---|
| 合成 test | 100.00% | 100% | 100% |
| 真实 test | 5.77% | 14.4% | 40.0% |

> 集成在合成同设计上不差于 HOG；但真实跨设计仍然很差，**不能吹成“更强模型”**。它的价值是候选投票/拒识/可解释，而不是替代目标域数据。

### 两副牌两槽分离（`TwoDeckSorter`）

用户工作流：同一标签**第一次确认 → A 槽**，**第二次确认 → B 槽**，第三次/UNKNOWN → 复核槽。

- 规则：`src/two_deck_manager.py`；
- 两副无王：104 张，A/B 各期望 52；
- 两副含王：108 张，A/B 各期望 54（Joker 按每副 2 张分槽）；
- 实测：`two104 → A=52/52, B=52/52`；`two108 → A=54/54, B=54/54`。

> 重要逻辑：两副完全相同的无标记牌混洗后，**无法知道某张牌原来属于哪一副**。A/B 是“按同标签出现顺序重建出的两套”，不是物理来源。若每类恰好两张，A/B 各是一套完整牌；这不是“牌身份/来源识别”。

### 非训练集牌面（OOD）与角标语义兜底

训练数据只有一套标准牌面设计。遇到别的牌（例如《三国杀》的 7♠、其他品牌字体/边框/插画）时：

1. 先用模板相似度做**未知设计拒识**：相似度 < 0.55 时不再强行输出 52 类；
2. **角标语义兜底（新增）**：OOD 时自动裁剪角标，用 EasyOCR 读 rank，再用 HOG 的 top1 花色组合成标签；
   - 三国杀 7♠ 实测：无需登记模板，输出 **7S**，`model=corner_semantic`；
   - EasyOCR 首次使用会下载检测/识别模型（约百 MB）；无网络/依赖缺失时仍回退 `UNKNOWN`；
   - 兜底只在单张/摄像头路径启用；批次默认关闭，避免真实照片被误接受。
3. 若角标也读不出，可人工输入标签并“登记当前牌为新模板”；
4. 模板保存到 `data/templates/<label>_custom_*.png`，同一设计以后可直接模板匹配。

> 角标语义是“读角上的字和花色”，不是 52 类整牌闭集；但它依赖角标存在、可读、方向能找到。
> 无标准角标的艺术牌/塔罗牌仍会拒识。整牌模型仍用于花色提示和已知设计校验。

### 用户样张登记

`data/templates_user/` 保存用户提供的样张（全图归一化模板），推理时优先匹配并返回“用户样张（已登记）”。
本轮已登记 `test_1`–`test_5`、`test_jd`、`test_ah`、三国杀 7♠ 共 8 张，实测全部识别正确。
这是**少样本登记/复现**，不是零样本泛化；新的未知牌面仍会走 OOD → 角标语义/登记。

样例实测：三国杀 7♠ 角标兜底为 **7S**；登记自定义模板后同样可识别为 `7S / custom_match`。
完整原因分析与改进记录见 [CASE_ANALYSIS.md](CASE_ANALYSIS.md)。

外部新牌面测试（13 张 MIT PNG，组合 10/13、花色 12/13）见 [EXTERNAL_TEST.md](EXTERNAL_TEST.md)。

OOD 门实测（`outputs/ood_eval.md`）：合成同设计误拒 **1.5%**（260 张），真实另一套设计拒识 **90.4%**（104 张）。
说明 OOD 门在同设计上基本不误伤；角标兜底只对可读角标放行。

### 人工兜底

- 单张图片自动检测失败时，可在界面上**手动拖框**选中牌面，再按裁剪区域识别；
- 批次日志详情可**人工修正标签**，同步修正批次计数；容量冲突会回滚，不静默改状态。

## 8. 已知限制与未验证项

1. **Joker 视觉识别未实现**：无 Joker 数据；批次支持 Joker 计数，但演示 Joker 是模拟事件。
2. **真实牌泛化未验证**：真实测试只有一套牌设计、每类同一实体牌重复拍摄；29.81% 说明域偏移严重，必须用团队自己的 2–3 副实体牌按“实体牌身份”重新划分验证。
3. **机械/ESP32 未接入**：`SerialSortingController.execute()` 明确抛 `NotImplementedError`，没有伪称硬件运行。
4. **摄像头**：本机摄像头可用（实际读帧测试通过），但不同电脑可能没有；界面会显示真实失败原因，图片模式仍可用。
5. **原始图像 vs 固定 ROI vs 透视校正的完整消融**未全部完成；现有指标来自统一校正流水线，不能据此声称某一步一定最优。
6. **分数不是概率**：模板 NCC/softmax 均未做概率校准；阈值来自验证集。
7. 演示 104 张来自合成测试集（同设计），不能作为真实牌准确率证据。
8. 后续 3 轮迭代与完整路线见 [NEXT_PLAN.md](NEXT_PLAN.md)；当前只解决检测/OOD/人工修正/登记，不等于解决任意牌面零样本识别。

## 9. 硬件接入说明

- `src/controller.py`：`SortingController.command(label)` 返回槽位/动作；模拟 `execute()` 只记录，不驱动机电。
- 真实实现：继承 `SortingController(simulated=False)`，在 `execute()` 中通过串口发送 `BIN_*`，等待 ACK/超时；失败必须抛异常并让批次记录失败，不能静默。
- 界面中的“分拣（模拟）”字段就是该接口的返回值，不表示机械已动作。
- 建议 ESP32 协议：`CMD:<BIN>\n` → `ACK:<BIN>\n`；超时 500 ms；急停优先。
